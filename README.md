# Chaos Bot
一個基於 Python、OpenCV 與 ADB 的跨平台遊戲自動化中樞。透過圖形化介面 (GUI) 提供操作設定，底層實作多執行緒 (Multithreading) 與狀態機 (FSM) 邏輯，徹底解決傳統腳本容易因畫面延遲或動態特效而卡死的問題。本系統專為長期掛機與高穩定度需求而設計，具備主動異常攔截與日誌記錄能力。

---

## 專案概述 (Overview)

本專案旨在解決 Rouge 類型遊戲中大量重複性農素材的勞動，透過電腦視覺與自動化流程建立「高穩定度的無人值守工作流」。

**核心能力：**
- **Visual Recognition：** 運用 OpenCV 特徵比對 (Template Matching)，動態判斷遊戲當下狀態。
- **Device Control：** 透過 ADB 深度串接模擬器，進行精準的座標點擊與滑動模擬。
- **Decoupled Architecture：** 實作 PySide6 與 QThread，將 UI 渲染與背景辨識邏輯解耦。
- **Exception Prevention：** 內建 Watchdog 看門狗機制與自動截圖存證，將系統由「被動錯誤中斷」升級為「主動預防錯誤」。
- **State Management：** 透過 JSON 實現輕量化狀態持久儲存，記憶使用者的介面配置。

---

## 系統流程 (System Workflow)

1. **參數配置：** 透過 GUI 讀取 `bot_config.json`，讓使用者自訂目標關卡與隊伍配置。
2. **設備連線：** 初始化 ADB 連線，動態綁定至指定模擬器通訊埠 (預設 127.0.0.1:16384)。
3. **狀態辨識：** 背景 Worker 持續擷取模擬器畫面，比對 `images/` 資料夾中的特徵圖庫。
4. **決策執行：** 基於狀態機邏輯，自動導航首頁、進入分類看板、點擊關卡，並自動執行體力消耗最大化設定。
5. **例外攔截：** 若偵測到體力耗盡，自動終止任務；若連續辨識失敗達 3 次，啟動看門狗喚醒機制並儲存異常截圖。

## 核心功能與工程亮點 (Engineering Highlights)

- **UI 與運算解耦架構：** 解決傳統自動化腳本執行時會造成介面卡死的問題。透過 `QThread` 獨立執行 ADB 與 OpenCV 運算，並利用 `Signal` 安全地與主執行緒 (PySide6) 進行通訊，確保 GUI 隨時保持流暢回應。
- **智慧防呆與看門狗 (Watchdog) 機制：** 捨棄死板的絕對座標點擊。系統會動態計算特徵圖的中心座標進行互動；當遇到未知畫面或動態特效干擾時，系統不會崩潰，而是觸發防呆喚醒機制 (點擊安全區域)，並自動擷取當下畫面 (`fail_cases`)，為未來的深度學習模型累積真實錯誤數據。
- **自適應睡眠排程 (Smart Sleep)：** 將長秒數的等待時間切碎為 0.1 秒的微小週期。這使得系統在長時間等待遊戲載入動畫時，依然能「即時」響應使用者的強制停止指令。
- **I/O 重定向日誌系統：** 實作 `StreamRedirector` 攔截底層標準輸出 (`sys.stdout`)，將後端執行狀態、警告與報錯，即時且非同步地廣播並渲染至前端 UI 的日誌終端機中。

## 開發挑戰與解決方案 (Challenges & Solutions)

### 1. 遊戲動態特效導致特徵比對失效
- **問題：** Rogue 類型卡牌遊戲的局內戰鬥充滿隨機的視覺特效與動態介面，傳統 Template Matching 容錯率低，容易導致自動化流程卡死。
- **解法：** 第一階段導入動態相似度閾值 (`max_val > 0.9`) 與狀態機重試機制。若連續迷失，則啟動 Watchdog 截圖存證並寫入 Log。此機制成功將系統轉化為「數據收集器」，為第二階段導入 AI 模型奠定資料基礎。

### 2. 多執行緒下的 UI 阻塞與崩潰
- **問題：** 若直接在主程式中呼叫 `time.sleep` 或進行繁重的截圖比對，會導致 Windows 判定程式無回應 (Not Responding)。
- **解法：** 嚴格遵守 Qt 框架規範，將核心邏輯封裝至繼承自 `QThread` 的 `BotWorker` 中，並透過 Qt Signals 傳遞執行狀態，實現完美的非同步 UI 更新。

### 3. 不可預期的體力耗盡與彈窗阻擋
- **問題：** 掛機過程中若體力耗盡，遊戲會跳出購買彈窗，導致後續的點擊邏輯全部錯位。
- **解法：** 在進入戰鬥的邏輯節點中加入「體力不足彈窗」的偵測分支。偵測到後自動點選取消，並透過變數 (`attempts`) 控制嘗試次數上限。若達上限則安全地自我終止 (Graceful Shutdown) 並保存最終 Log。

## 快速啟動 (Quick Start)

### 1. 建立環境
```bash
conda create -n chaos_bot python=3.10 -y
conda activate chaos_bot
```

### 2. 安裝依賴
```bash
pip install -r requirements.txt
```

### 3. 模擬器設定
請確保已啟動 Android 模擬器 (如 MuMu, Nox, LDPlayer)，並開啟 ADB 除錯模式。預設連線通訊埠為 127.0.0.1:16384 (可於 bot_worker.py 中修改)。

### 4. 啟動系統
```bash
python main_ui.py
```
